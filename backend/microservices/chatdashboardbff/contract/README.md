# chatdashboardbff API contracts

This service sits on both sides of a contract, so there are two:

- **Exposed (REST)**: `openapi.yaml` — the OpenAPI 3.1 spec for the BFF's own
  REST API, generated by springdoc-openapi from the annotated controllers
  (snapshot of the live `/v3/api-docs.yaml`, same convention as chatservice's
  `contract/openapi.yaml`). Deliberately the same REST surface chatservice
  exposes (paths, DTO shapes, status codes) — one dashboard-facing contract,
  regardless of which backend serves it.
- **Consumed (gRPC)**: `../src/main/proto/tenant.proto` — a **copy** of
  accountservice's contract (`backend/microservices/accountservice/src/main/proto/tenant.proto`),
  compiled into client stubs by the same protobuf-maven-plugin. It's a copy,
  not a shared module, because there are exactly two users so far — if the
  files drift, builds still pass but calls break at runtime, so **any change
  to accountservice's proto must be copied here** (and vice versa never:
  accountservice owns this contract, the BFF just consumes it). Promote to a
  shared proto/stub module when a third consumer appears, not before.

## Regenerate the REST contract

```bash
# 1. accountservice doesn't need to be running for this - only Postgres-free
#    startup of the BFF itself (gRPC channels connect lazily).
# 2. From backend/microservices/chatdashboardbff:
./mvnw.cmd spring-boot:run
# 3. In another shell:
curl http://localhost:8100/v3/api-docs.yaml -o contract/openapi.yaml
```

Swagger UI: `http://localhost:8100/swagger-ui.html`. BootUI dev console:
`http://localhost:8100/bootui`. Both while the app is running.
